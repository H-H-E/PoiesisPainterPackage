## Source-versus-runtime caution

The upstream [performance report](https://github.com/lambentLogic/wet-edge/blob/e4ce2ec7a37d85c17ad16bb3006959bb88a19a73/docs/PERFORMANCE.md#L25-L56) includes experiments whose behavior changed; it is not a hardware-agnostic guarantee or an independent measurement. Rendering cost is high even with active tile dispatch when substantial wet area is active; GPU capabilities alone do not establish lower latency than Canvas2D. The paper stages and mixed pigments cannot be substituted with one color/opacity number.

## Minimal reproduction — **specified, not run**

In locked checkout `../references/wet-edge`, run `npm install`, `npm run serve` and open `http://127.0.0.1:8765/` in a WebGPU-capable browser. Use [tools/paint.mjs](https://github.com/lambentLogic/wet-edge/blob/e4ce2ec7a37d85c17ad16bb3006959bb88a19a73/tools/paint.mjs#L1-L45) to run a minimal script with a deterministic sheet seed, one blue paint stroke, one clean-water stroke, `sim.sense` before/after, `sim.look('before')`, wait for dry stage then `sim.look('after')`. Repeat with rewet or blot, capture full save, PNG and color-level raw probes. Verify `navigator.gpu` and device features first; explicitly record `blocked` if unavailable. Probe `sim.undo()/redo()` against a stored snapshot or final pixels; record stage transitions and elapsed simulated time.

For throughput, use `npm run measure` and [performance probes](https://github.com/lambentLogic/wet-edge/blob/e4ce2ec7a37d85c17ad16bb3006959bb88a19a73/tools/probes.js) on an otherwise idle host; record GPU adapter, pixel count, wet coverage, iterations, medians and output hashes. Never compare upstream M3-Pro ratio to a Poiesis timer on another machine.

Compare to Poiesis's [watercolor scene](../../examples/scenes.mjs#L54-L69), [watery-edge study](../../examples/scenes.mjs#L105), [MaterialSurface.step](../../src/materials.ts#L249-L282), and [unit tests](../../tests/materials.test.mjs#L9-L24). Reproduction details/acceptance criteria for WE01–WE09: [probes.md](probes.md).
